## 1. 学習目標

**今日の主な目標：** Vue.jsを使い、メモの登録・一覧表示・編集・削除を行う画面を、データと画面の関係を考えながら自分で設計・実装する。

**理解を確かめる方法：** 作成・選択・保存・削除の各操作で、どのデータが変わり、画面に何が表示されるかを自分の言葉で説明できること。特に、新規保存と更新保存の違い、保存済みメモと編集中の入力を分ける理由を説明できること。

自分の欲しいメモ帳を実装するという目的を残し、出来上がった動作と設計の一致は、第2章の完了条件と第5章の検証結果で確認する。

自分が楽にメモをし、管理しやすくするためのアプリ。利用者は自分とし、ローカルのブラウザで使用する。

## 3. 設計

### 3.1 画面・入出力

**画面構成：** メモ一覧と編集欄を同じ画面に表示する。画面遷移は行わず、一覧の選択に応じて編集欄の内容を切り替える。

| 領域 | 表示・操作する内容 |
|---|---|
| 作成操作 | 「作成」ボタン。編集欄を空にして新規作成状態にする |
| メモ一覧 | 保存済みメモのタイトルをメモタブとして表示する。各メモに「削除」ボタンを設け、選択中のメモを見分けられる表示にする |
| 編集欄 | タイトルの1行入力欄、本文の複数行入力欄、「保存」ボタン。入力エラーは対応する入力欄の近くに表示する |
| 0件の表示 | 一覧に「メモはありません」と表示し、「作成」「保存」は操作可能にする。初期表示や最後の選択中メモを削除した直後は編集欄を空にする。新規入力中に非選択の最後のメモを削除した場合は、入力内容を維持する |

一覧は新規保存順とし、新しいメモを末尾へ追加する。既存メモを編集しても表示順は変えない。削除操作が、メモタブの選択操作も同時に実行してしまわないようにする。

| 操作 | 入力・前提 | 出力・期待する状態 |
|---|---|---|
| 初期表示 | 保存済みメモ0件、選択なし | 0件の案内と空の編集欄を表示する |
| 作成ボタンのクリック | 現在の選択状態・編集中の入力 | 未保存の入力を確認なしで破棄し、選択を解除してタイトル・本文・入力エラーを空にする。この時点ではメモを一覧へ追加しない |
| タイトル・本文の入力 | 新規作成中、または既存メモを選択中 | 編集用データだけを変更する。保存済みメモと一覧表示には、まだ反映しない |
| 保存ボタンのクリック：新規 | 選択なし。有効なタイトル・本文 | 新しいIDを持つメモを1件追加し、そのメモを選択する。入力エラーを消す |
| 保存ボタンのクリック：既存 | 選択中メモのID。有効なタイトル・本文 | そのIDのメモだけを更新する。件数・ID・表示順を変えず、選択を維持する。入力エラーを消す |
| 保存ボタンのクリック：入力不正 | タイトルまたは本文が空欄・空白だけ | 保存せず、該当欄にエラーを表示する。編集中の入力と保存済みメモを維持する |
| 一覧内の別のメモタブをクリック | 選択先メモのID | 未保存の入力を確認なしで破棄する。選択先メモのタイトル・本文を編集用データへコピーし、入力エラーを消す |
| 一覧内の選択中メモタブを再クリック | 現在と同じメモのID | 状態を変更しない。未保存の入力と表示中の入力エラーを保持する |
| 選択中メモの削除ボタンをクリック | 削除対象のIDが選択中のIDと同じ | 確認ダイアログなしで対象を削除する。選択・編集入力・入力エラーをクリアし、空の新規作成状態にする |
| 選択していないメモの削除ボタンをクリック | 削除対象のIDが選択中のIDと異なる。または新規作成中 | 確認ダイアログなしで対象だけを削除する。現在の選択・編集中の入力・入力エラーは変更しない |

### 3.2 データ

**保存方法：** ブラウザのメモリのみ。保存済みメモと編集中の入力を分けて保持する。DB・ファイル・ブラウザストレージには保存しない。

#### 保存済みメモ

保存済みメモは `memos` という配列で保持する。1件のデータは次の3項目で構成する。

| テーブル・データ名 | 項目 | 型 | 制約・ルール |
|---|---|---|---|
| メモ | `id` | 数値 | ページ内で一意の正の整数。新規保存の成功時だけ採番し、編集では変更しない |
| メモ | `title` | 文字列 | 空欄・空白だけは不可。同じタイトルのメモは許可する |
| メモ | `content` | 文字列 | 空欄・空白だけは不可。本文の改行を保持する |

タイトル・本文の空欄判定では、前後の空白・タブ・改行を除いた結果が空かどうかを確認する。判定には `trim()` を使うが、保存する文字列自体は入力された値を保持する。今回、独自の文字数上限は設けない。

#### 画面と処理の状態

| データ名 | 型 | 用途・初期状態 |
|---|---|---|
| `memos` | メモの配列 | 保存済みメモの一覧。初期値は空配列 |
| `selectedMemoId` | 数値または `null` | 編集対象をIDで特定する。初期値は `null`。`null` は新規作成状態を表す |
| `draftTitle` | 文字列 | 編集中のタイトル。初期値は空文字 |
| `draftContent` | 文字列 | 編集中の本文。初期値は空文字 |
| `validationErrors` | オブジェクト | タイトル・本文それぞれのエラーメッセージを保持する。初期値は各欄とも空文字 |
| `nextMemoId` | 数値 | 次の新規保存で使うID。初期値は1。保存成功後に1増やし、削除後も巻き戻さない |

**データ間の関係：** DBのテーブル間の関係はない。`selectedMemoId` で `memos` 内の編集対象を特定する。編集用のタイトル・本文には値をコピーし、保存済みメモを入力操作で直接書き換えない。タイトルや配列上の位置を、メモを識別する基準にはしない。

**保持期間：** 表示中のページが動作している間だけ保持する。アプリ起動時は初期状態を作る。再読み込み・タブを閉じて再度開く操作では、以前のメモを復元しない。別タブとの共有・同期も行わない。

**検証データ：** 初期データファイルは作らず、必要に応じて次のメモを画面から手入力する。テスト開始時の状態は第5章に記録する。

| 用途 | タイトル | 本文 |
|---|---|---|
| 基本データ1 | 買い物 | 牛乳を買う |
| 基本データ2 | 作業 | READMEを確認する |
| 基本データ3 | 予定 | 学習時間を確保する |
| 同じタイトルの識別確認 | 買い物 | パンを買う |
| 編集・改行確認 | 買い物（更新） | 「牛乳を買う」「卵を買う」を改行で区切って入力する |
| 不正入力の確認 | 空文字、半角空白のみ、全角空白のみ | 空文字、空白・タブ・改行のみ。片方を有効な入力にしたケースと、両方が不正なケースを確認する |

### 3.3 処理の構成

**処理の流れ：** 新規作成またはメモ選択 → 編集用データへ入力 → 保存時に入力検証 → 新規追加または既存更新 → メモ一覧・編集欄へ結果を反映する。

**役割の分け方：** 次の責務を区別する。ただし、各役割を必ず別ファイル・別コンポーネントにすることは要求せず、小規模な構成で実装する。

| 役割 | 担当する内容 |
|---|---|
| UI表示・操作受付 | 一覧・編集欄・選択状態・入力エラーを表示し、クリックや入力を受け付ける |
| 編集状態の管理 | 新規作成、選択、編集用データへのコピー、未保存の入力の破棄を扱う |
| 入力検証 | 保存前にタイトル・本文を確認し、入力欄ごとのエラーを返す |
| メモの保存・削除 | 新規IDの採番、IDに対応するメモの追加・更新・削除を行う |

**更新の確定・取り消し：** DBのトランザクションは扱わない。画面上の変更は、有効な入力で「保存」を押した時点で確定する。保存前の文字入力では保存済みメモを変更しない。

別メモの選択・新規作成では、未保存の入力を確認なしで破棄する。既存メモの保存前の編集を破棄しても、保存済み内容は変えない。新規メモを保存せずに離れた場合は、一覧へ追加しない。保存済みの変更や削除を元に戻す機能は作らない。

**エラー表示の更新：** 入力検証は保存時に行う。入力し直しただけでは直前のエラー表示を変更せず、次の保存時に再判定する。新規作成・別メモの選択・選択中メモの削除・保存成功時には、入力エラーをクリアする。

### 3.4 異常時の動作

通常操作の境界状態も含め、次のように扱う。

| 状況 | 想定する動作・守るべき状態 |
|---|---|
| タイトルが空欄・空白だけ | 保存せず、タイトル欄に「タイトルを入力してください。」と表示する。保存済みメモと編集中の入力を維持する |
| 本文が空欄・空白だけ | 保存せず、本文欄に「本文を入力してください。」と表示する。保存済みメモと編集中の入力を維持する |
| タイトル・本文の両方が不正 | 両方のエラーを表示する。一部の項目だけを保存しない |
| 未保存の入力がある状態で別メモを選ぶ | 確認なしで未保存の入力を破棄し、選択先の保存済み内容を表示する |
| 未保存の入力がある状態で作成ボタンを押す | 確認なしで未保存の入力を破棄し、空の新規作成状態にする |
| 同じメモを再選択する | 未保存の入力を破棄しない |
| 選択中のメモを削除する | メモとその未保存の入力を破棄し、空の新規作成状態にする。ほかのメモを自動選択しない |
| 選択していないメモを削除する | 対象のメモだけを削除し、現在の編集状態を維持する |
| メモが0件 | 「メモはありません」と表示し、新規作成・保存を可能にする。初期表示や選択中メモの削除では編集欄を空にするが、新規入力中に非選択の最後のメモを削除した場合は入力を維持する |
| 再読み込み・タブを閉じて再度開く | 保存済みメモも未保存の入力も復元しない。終了時の確認・自動退避は行わない |

### 3.5 設計判断

**採用した技術・構成：** JavaScript、Vue.js、Docker。メモの処理とデータ保持はブラウザ内で行う。

**採用理由と見送った案：** JavaScript・Vue.jsを使い、入力・データ・表示の関係と、メモ操作に伴う状態の変更を学ぶために採用する。今回、他の言語・フレームワークとの比較は行わず、後日の比較課題で扱う。採用技術が他の選択肢より優れていると評価したものではない。

DockerではVue.jsアプリの開発サーバーを起動し、ブラウザからローカルのアプリを開く。Docker内へメモを保存する構成ではない。具体的な環境・バージョン・起動コマンド・ポートは、構築時に第4章へ記録する。

元の方針どおりブラウザのメモリのみを使用し、DB・永続保存は追加しない。今回は画面とデータの扱いを中心とし、複雑な層構造や共通ライブラリは導入しない。

**今回の修正で具体化した判断：** 削除機能の実装と、レビューで示した基本の完了条件はユーザー確認済み。次の項目は元のREADMEで未記入、またはレビューで選択肢として示した内容を、修正依頼に基づいて本版で具体化したもの。

| 項目 | 本版で採用する動作・構成 |
|---|---|
| 画面 | 一覧と編集欄を同じ画面に配置する |
| 保存 | 編集用データを分離し、保存時だけ新規追加または既存更新する |
| 入力 | タイトル・本文は両方必須。空白だけは不可。独自の文字数上限は設けない |
| メモの識別・順序 | ページ内の連番IDで識別し、新規保存順で末尾へ追加する |
| 未保存の変更 | 別メモの選択・新規作成では確認なしで破棄する。同じメモの再選択では維持する |
| 削除 | 確認ダイアログなし。選択中なら編集欄を空にし、非選択なら現在の編集状態を変えない |
| 保存期間 | ページ内のみ。再読み込み後・タブを閉じた後は復元しない |
| 検証 | 小さなデータを手入力し、各完了条件を確認する。実行結果は検証後に記入する |

**実装中の変更：** なし。実装中に設計を変更した場合は、変更前後・理由と、完了条件への影響をここへ記録する。
