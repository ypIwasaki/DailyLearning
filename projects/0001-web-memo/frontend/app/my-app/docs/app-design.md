# Webメモ アプリ設計書

作成日：2026-09-28  
対象：`projects/0001-web-memo/frontend/app/my-app`  
本書は、実装前に合意する機能仕様、データ構造、コンポーネントの責務、処理方針、受け入れ条件を定義します。記載内容は実装で満たすべき設計であり、実装済み・検証済みであることを示しません。

## 1. 目的と対象範囲

タイトルと本文を持つメモを、同じ画面で登録・一覧表示・編集・削除する学習用アプリです。Vueによる入力状態の管理、コンポーネント間のイベント連携、IndexedDBの非同期操作を学びます。

利用者はローカルのブラウザで操作します。サーバーAPIやサーバー側DBは使用せず、Dexieを通してブラウザのIndexedDBに保存します。保存済みメモは再読み込み後も読み出します。入力途中の内容と編集対象の選択は永続化しません。

認証、検索、並び替えUI、書式編集、バックアップ・エクスポート、複数タブの同期、削除後のUndoは今回の対象外とします。

## 3. 画面設計

画面遷移のない単一画面です。上部にヘッダー、その下に編集欄とメモ一覧を配置します。

| 領域 | 表示と操作 |
|---|---|
| ヘッダー | アプリ名、説明文 |
| 編集欄 | タイトル、本文、新規作成／編集中の表示、「新規作成」「メモを保存」ボタン |
| 一覧 | 保存件数、各メモのタイトル、本文の最大2行のプレビュー、「編集」「削除」ボタン |
| 0件の案内 | 「メモはまだありません」と新規保存を促す説明 |

タイトルは1行入力、本文は複数行入力です。入力欄にはラベルを設け、操作ボタンにはキーボードフォーカスを表示します。一覧のスクロール領域はキーボードでもフォーカスできます。

### レイアウトとスクロール

- アプリの高さを表示領域の高さに固定し、ページ全体のスクロールを抑止します。
- 幅760pxを超える画面では編集欄と一覧を左右に配置し、同じ高さに伸ばします。列の比率は概ね3対2です。
- 一覧は見出しと件数を固定し、メモのリスト内で縦スクロールします。
- 編集欄の内容が収まらない場合は編集欄内で縦スクロールします。
- 幅760px以下では編集欄と一覧を上下に配置し、利用可能な高さを等分します。

## 4. データ設計

### 4.1 IndexedDB

DB名：`MemoDatabase`  
スキーマバージョン：`1`  
オブジェクトストア名：`memos`

```js
db.version(1).stores({
  memos: '++id, title, createdAt, updatedAt'
})
```

| 項目 | アプリが保存する型 | 用途・ルール |
|---|---|---|
| `id` | 数値 | 主キー。新規登録時に自動採番し、更新時は維持する |
| `title` | 文字列 | タイトル。空欄・空白だけは保存不可。同じタイトルを許可する |
| `content` | 文字列 | 本文。空欄・空白だけは保存不可。入力された改行を保持する |
| `createdAt` | Date | 新規保存時の日時。更新では変更しない |
| `updatedAt` | Date | 最後に保存した日時。新規登録時は作成日時と同じ |

`title`、`createdAt`、`updatedAt` はインデックスです。`content` はインデックス定義に含まれませんが、レコードの値として保存します。上記の型と必須チェックはアプリ側の扱いであり、`stores()` が必須項目や型を検証するわけではありません。

保存先はブラウザのオリジンごとに分かれます。同じブラウザ・同じオリジンで利用することを前提とし、ブラウザデータの削除等による消失からの復元機能はありません。

### 4.2 コンポーネントの状態

| コンポーネント | 状態 | 初期値 | 用途 |
|---|---|---|---|
| Edit | `title` | 空文字 | 編集中のタイトル。inputの`v-model`と連動 |
| Edit | `content` | 空文字 | 編集中の本文。textareaの`v-model`と連動 |
| Edit | `selectedMemoId` | `null` | `null`なら新規作成、数値なら既存メモの編集 |
| List | `memos` | 空配列 | DBから取得した一覧の表示用データ |

入力はEditの状態だけを変更します。保存ボタンを押すまではDBとListの一覧データには反映しません。

## 5. コンポーネント間の連携

AppはDBを直接操作せず、兄弟コンポーネントの連携を仲介します。

| 接続 | 内容 |
|---|---|
| `<Edit ref="memoEditor" @saved="refreshMemos" />` | 編集欄を参照可能にし、保存完了を受け取る |
| `<List ref="memoList" @edit="editMemo" />` | 一覧を参照可能にし、編集対象のIDを受け取る |
| Edit → App：`saved` | 保存完了の通知。引数なし |
| List → App：`edit` | 編集操作の通知。メモのIDを渡す |
| List → App：`deleted` | 削除完了の通知。削除したメモのIDを渡す |
| App → List：`loadMemos()` | DBから一覧を再取得する |
| App → Edit：`loadMemo(id)` | IDに対応するメモを読み込む |
| App → Edit：`clearDeletedMemo(id)` | 削除対象が編集中なら新規作成状態に戻す |

```text
Edit.saveMemo → DBに保存 → savedイベント
    → App.refreshMemos → List.loadMemos → 一覧更新

Listの編集ボタン → editイベント（ID）
    → App.editMemo(ID) → Edit.loadMemo(ID) → 入力欄更新

Listの削除処理 → DBから削除 → 一覧再取得・deletedイベント（ID）
    → AppがEditへ通知 → 編集対象と同じIDなら編集欄を初期化
```

## 6. 処理設計

### 6.1 初期表示と一覧取得

1. Editを空の新規作成状態で表示する。
2. Listの`mounted()`から`loadMemos()`を呼ぶ。
3. `db.memos.toArray()`の結果を`memos`へ代入する。
4. `v-for`で表示し、`memo.id`を各行のキーにする。

一覧の表示順はIDの昇順（新規登録順）とします。既存メモの更新では表示順を変更しません。取得処理ではこの順序を維持します。

### 6.2 新規登録と更新：Edit.saveMemo()

1. `title.trim()`と`content.trim()`で空欄・空白だけの入力を判定する。
2. 不正ならalertを表示し、DB操作を行わず終了する。入力値は維持する。
3. 現在日時を生成する。
4. `selectedMemoId === null`なら`db.memos.add()`で登録し、返されたIDを`selectedMemoId`に保持する。
5. 既存IDなら`db.memos.update()`でタイトル・本文・更新日時を更新する。更新件数が0なら対象なしのalertを表示して終了する。
6. 成功時に`saved`イベントを通知し、App経由で一覧を再取得する。
7. 保存成功のalertを表示する。

`trim()`は検証にだけ使い、保存する値は入力された文字列のままとします。新規保存後の再保存は同じIDの更新として扱います。保存後も入力欄は維持します。保存成功の通知はDBへの書き込み完了を意味し、一覧の再取得は通知を受けたAppから別途開始します。

### 6.3 編集対象の読み込み：Edit.loadMemo(id)

1. 同じIDが選択中なら終了し、入力途中の内容を維持する。
2. `db.memos.get(id)`で対象を取得する。
3. 対象がなければalertを表示し、現在の編集状態を維持する。
4. 対象のID・タイトル・本文をEditの状態へ代入する。

別メモを読み込むと、未保存の入力は確認なしで置き換わります。

### 6.4 新規作成：Edit.startNewMemo()

`selectedMemoId`を`null`にし、タイトル・本文を空にします。この操作だけではDBに登録しません。未保存の入力は確認なしで破棄します。

### 6.5 削除：List.confirmDelete(memo)

1. ブラウザ標準の`window.confirm()`で「『対象メモのタイトル』を削除しますか？」と表示する。
2. キャンセルなら終了する。
3. OKなら`db.memos.delete(memo.id)`で対象を削除する。
4. `loadMemos()`で一覧を再取得する。
5. 削除したIDを`deleted`イベントでAppへ通知する。AppはEditへ通知し、編集中のIDと一致する場合のみ編集欄を初期化する。

編集中のメモを削除した場合は、選択ID・タイトル・本文をクリアし、新規作成状態に戻します。別のメモを削除した場合は、編集中の入力と選択IDを維持します。削除成功後に他のメモを自動選択しません。

## 7. エラー処理と設計上の制約

| 操作 | エラー時の表示・動作 |
|---|---|
| 保存 | Consoleに記録し、失敗のalertを表示する |
| 編集対象の取得 | Consoleに記録し、読み込み失敗のalertを表示する |
| 一覧取得 | Consoleに記録する。画面に専用のエラー表示はない |
| 削除 | Consoleに記録し、削除失敗のalertを表示する |

今回の設計では、入力エラーや保存・削除の結果にブラウザ標準のダイアログを使用します。一覧取得エラーの専用UI、処理中の表示、連打や同時操作の制御は追加検討事項とし、今回の受け入れ条件には含めません。別タブの変更は自動反映せず、ページを再読み込みして取得します。

DB操作に失敗した場合は成功イベントを通知せず、保存成功・削除成功として扱いません。保存失敗時は編集入力を維持し、利用者が再操作できる状態とします。

## 9. 受け入れ条件と検証計画

実装後は、以下の正常系・異常系・境界値を手動で確認します。各項目の結果は検証記録へ記載し、全条件を満たしたことを確認して完了とします。

| 項目 | 確認する動作 |
|---|---|
| 新規保存 | 件数が1増え、保存後の再保存では増えない |
| 入力検証 | タイトル・本文の空欄や空白だけの入力を保存しない |
| 永続化 | 再読み込み後に保存済みメモが表示される |
| 編集 | 対象の内容を表示し、保存後に件数とIDを維持して更新する |
| 未保存入力 | 同じメモの再選択では維持し、別メモや新規作成では破棄する |
| 削除 | キャンセルで維持し、OKで対象IDだけを削除する |
| 削除確認文 | 削除対象のタイトルが表示される |
| 編集中の削除 | 編集対象を削除すると空の新規作成状態に戻る。他のメモの削除では入力を維持する |
| 同名メモ | 同じタイトルでもIDで編集・削除対象を区別する |
| スクロール | 多数のメモでもページ全体は動かず、一覧内をスクロールできる |
| 狭い画面 | 上下配置となり、各領域内で操作できる |
| 対象なし | 存在しないIDの読み込み・更新を成功として扱わない |
| 保存失敗 | 成功通知を出さず、入力を維持する |

検証には本文の異なる同名メモ、改行を含む本文、空文字・半角／全角空白だけの入力、スクロールが必要な件数のメモを用意します。DB内容の確認では保存後に値を再取得し、一覧表示だけで永続化の成否を判断しません。
